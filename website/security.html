NEXORA Security & Safety Model

Safety before cleaning. How NEXORA mathematically guarantees your personal files and operating system files remain untouched.

1. Path Traversal & Boundary Control

All candidate targets are normalized and checked for directory traversal sequences (..) and alternate data streams prior to resolution. The root drives (C:\, D:\) and operating system core folders (C:\Windows\System32, SysWOW64, WinSxS) are hardcoded blacklists that can never be modified.

2. User Personal Document Shields

NEXORA strictly excludes standard personal directories: Documents, Desktop, Pictures, Videos, Music, OneDrive, and Dropbox. Even if a temporary file is placed inside a personal folder, the engine denies unlinking.

3. Symlink & Junction Hijack Protection

Malicious programs often use NTFS junctions or symlinks pointing from temporary folders into sensitive system roots. NEXORA's Rust directory walker strictly enforces follow_links(false) and verifies reparse point metadata before examining any path.

4. Anti-TOCTOU Double Validation

To prevent Time-of-Check Time-of-Use race conditions, NEXORA re-validates every individual path immediately before calling the native file move or unlinking API. If target attributes change between scan and clean, the file operation is automatically aborted.

Vulnerability Disclosure Policy

We take cybersecurity and user data protection seriously. If you believe you have discovered a security weakness or potential bypass in our boundary model:

  • Report it directly to our security team at: security@nexora.app
  • Include reproduction steps, version details, and expected vs observed behavior.
  • We acknowledge vulnerability reports within 24 business hours and prioritize patches within 72 hours.
